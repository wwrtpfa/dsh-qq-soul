01

记忆是怎么设计的

她不是把聊天记录整段背下来，而是把「值得记住的事」摘成一张张小卡片存起来。每轮回复前按你正在说的话翻出最相关的几条，悄悄垫进提示词里，于是显得「记得你」。全部只在这台电脑，默认进 SQLite，不上云。

纯本地默认开启
四层结构：items 长期事实、gists 梗概与印象、kv 小档案与相处经验、meta 顺序与集合清单。

一句话流程 6 步

  1. 消息进来先按天追加成一行聊天流水原话，这是临时层。
  2. 主人私聊说「记住…／忘掉…」，当场写库或把旧条目标为过时。
  3. 回复前拼上常驻的小档案、相处经验、说话方式，再按这句话检索出最多 4 条相关记忆垫进本轮。
  4. 每天 04:00、16:00（或空闲约 30 分钟）后台把流水交给模型提炼成长期事实。
  5. 写入前去重、合并、标过时、按来源限额淘汰，最后一个事务原子落盘；被想起过的条目标一次命中，忘得更慢。
  6. 下一轮消息进来，第 3 步重跑一次。

常见疑问

会不会把我的隐私传上云？

默认不会，记忆只在本机 memory.sqlite。只有手动打开「向量检索」并填了 embedding 地址，才会把记忆文字与查询发给那个地址。

换电脑怎么带走 / 记错了怎么让她忘？

用「系统」页的一键备份出 zip，或直接拷整个数据目录，恢复在下次启动生效。私聊发「忘掉…」即时标过时，也可在「记忆库」里改或删。

会不会越记越多撑爆？

不会：自动记忆按来源限额（默认共 3000 条），不重要的按遗忘曲线淡出，旧细节压成梗概与印象，聊天流水默认只留 7 天。

02

翻唱是怎么跑起来的

她不会真的开口唱。点歌后下载原曲，用程序拆出人声和伴奏，再用你导入的 .pth + .index 音色把原唱换成「她」的嗓子，混回伴奏，最后把 mp3 当成一条 QQ 语音条发回来。Node 插件点单，本机 9876 的 Python 服务做菜。

后台作业macOS 约 5 GB
同歌 + 当前音色 + 同模式会直接 reuse 成品；跨机部署时改从 /files/ 下载成品。

一句话流程 关键 6 步

  1. 【Node】QQ 发 /sing 小幸运 田馥甄（末尾 +12 升调），或模型调 qq_song_cover，或面板点「试唱」。
  2. 【Node】先查曲库，命中就放成品；否则 song-bridge 打包 POST 到 /song/request，服务没跑会先自动拉起一次。
  3. 【Python】回 202 + 作业号，后台线程跑七阶段管道，逐条写进 jobs/<id>.jsonl。
  4. 【Python】按音乐源顺序找歌下载 → demucs --two-stems=vocals 拆轨 → 用 RMS 找起唱点，人声、伴奏、混音同步裁剪不错位。
  5. 【Python】常驻 RVC 引擎用 .pth + .index 换声，ffmpeg 混音、轻混响、两遍响度归一到 -16 LUFS，输出 320k mp3 入库。
  6. 【Node】每 800ms 轮询取件，hub.sendVoiceFile 读成 base64，用 OneBot record 段发到原聊天。

卡住了看哪

点歌后没动静？

后台作业，先看「翻唱 → 作业日志」的阶段进度；服务没跑插件会自动拉一次，仍不行去「概览 → 音频服务」点「启动服务」。卡住 5 分钟、总耗时超 10 分钟会自动停下并回话。

为什么 macOS 约 5 GB、Windows 约 8 GB？

一键安装六步：独立 Python 3.12、固定版 Applio、PyTorch/RVC/audio-separator、ffmpeg、rmvpe + contentvec（约 560 MB）、BS-RoFormer（约 640 MB）。Windows 多装 CUDA 版 PyTorch，macOS 装 CPU/MPS 版。Intel Mac 不支持一键安装，只能接自己的 RVC 服务。

macOS 与 Windows 加速差在哪？

macOS 用 MPS，缺算子靠 PYTORCH_ENABLE_MPS_FALLBACK=1 退回 CPU；Windows 有 NVIDIA 独显走 CUDA/half。换声几分钟属正常，日志会写「换声 X／约 Y」并注明仍在跑。

03

一句话怎么变成语音条

她先把回复里「能念的字」挑出来，去掉表情和 emoji，交给朗读链路变成音频文件，最后以 base64:// 的语音段发回 QQ。发不发、用谁的声音念，由「语音」页开关和当前渠道决定；整条链路跨 Node 插件、本机 9876 Python 服务、QQ 网关三个进程。

自动拉起服务三级降级
降级顺序：9876 主链路 → 本机备用渠道（edge-tts / CosyVoice / 自定义 HTTP）→ 改发文字。

一句话流程 6 步

  1. 消息经 QQ 网关（正向 WS，默认 6700）进 Node 插件，先过白名单：主人 / 私聊白名单 / 群白名单。
  2. 大模型一轮结束后 deliverTurn 交给 parseReply 拆条；<voice> 标记或 voice.mode 判定哪些发语音。auto 模式下还要看对方是否明说「用语音」，或短回复是否命中 autoChance（默认 0.15）。
  3. sendVoice 用 splitSpeakable 去掉表情，只留纯文本，调语音模块的 speak。
  4. service.enabled 时 POST 到 9876 的 /tts/speak，带 Bearer token；服务没跑由 launcher 自动拉起。
  5. Python 侧 TTSEngine.speak 按标点分句逐段合成，ffmpeg 统一转 24000Hz 单声道 WAV，段间插 220ms 静音拼接；开「说话换声」再走一次 RVC。
  6. Node 读回文件转 base64，用 OneBot record 段发送，语音条单独成条、不带引用或 @。

04

她为什么主动找你说话

没人理她时，她不会马上凑上来：先等够时间、过完几道闸门，再从聊天和记忆里挑一件想跟你说的事，写一句话发到你的 QQ 私聊。不是复读问候，也不会在群里凭空喊你。默认是「总开关关、试运行开」，刚装好一句都不真发。

默认不真发一轮只发一处
铁律：一轮只发一处，绝不两头都发；结果不确定也不重发。专注模式开着则静默。

一句话流程 5 步

  1. 定时：两个模块各注册 60 秒一次的 tick，是自动触发的唯一定时源；没有「一闲就发」。
  2. 过闸门：总开关、试运行、禁言、醒着时段、安静时段、今日次数、间隔、主人空闲够不够，不过就改约下次。
  3. 二选一：默认「主动搭话」从预设由头随机挑；可选「目的引擎」默认关，开启后旧搭话会主动让路。
  4. 挑目的并生成：收最近两天私聊与群聊流水、长期记忆、人格卡和「心里惦记的事」，算九维驱动（想玩 / 想陪 / 想分享），去重轮换后加权随机挑一个；她可回「沉默」，算决定不说。
  5. 落地与回执：默认投主人私聊；改成桌宠且在线就走桌面气泡，离线按开关回落 QQ 或静默。真发出才结算心情与次数。

太吵或太安静怎么办

太吵

桌宠是怎么装起来、又是谁在管

桌宠不是本插件的内置模块，而是单独装进数据目录的社区模块；但它的面板、接口、开关、配置和状态全部由本插件掌控。「第三方」说的是代码来源，不是控制权归属。它跟 NapCat 也不一样：NapCat 是必须解耦的独立进程，pet 是被 import 进插件进程的同进程模块。

可选增强来源在外部
开关值存在插件自己的 config.json；解耦的是代码来源与发布节奏，不是控制权。模块在跑 ≠ 桌面上有窗口，还要 Electron 装好、进程启动。

一句话流程 6 步

  1. 插件启动扫 modules/pet/，把 index.mjs 以带时间戳的快照 import 进插件进程；16 个内置模块里没有 pet，它是 1.2.0 搬到社区库的。
  2. host.js 启动时注册 18 个 /panel/pet/* 代理路由；改 host 代码要重启 DSH，数据目录里的模块反而热重载。
  3. 面板每 8 秒拉一次 /panel/pet/status，拿到 宿主读到的真实版本、是否在跑、以及四个绝对路径；版本不写死在面板里。
  4. 卡里的开关统一写 ext.pet.*，由模块 api.settings() 读回；「主动搭话发 QQ 还是桌宠气泡」的载体总开关已收拢到这张卡，与「主动搭话 → 目的机制」卡写同一个 ext.purpose.carrier，两边改哪边都生效。
  5. 客户端与素材是另外两层：modules-data/pet/app/ 的 Electron 应用（运行时从镜像单独装）、packs/default-animation/ 的 106 段 webm。
  6. 模块在跑 + Electron 装好 + 进程启动，三者齐了才出现；主动搭话还要载体设成桌宠且在线，离线才按开关回落 QQ。

怎么调研的 可复现

  1. 先问宿主，不抄版本号：读 /panel/pet/status 的 module 与 paths，拿到「装的是谁、版本多少、装在哪」。
  2. 反查模块体系：BUILTINS 没有 pet → 再看 STABLE_ROUTES、MOVED.pet、CHANGELOG 的 1.2.0 记录，确认「从内置搬到社区库」。
  3. 看分组判定逻辑：status() 用 builtin 与 community 三分；.aurabot-source.json 是社区安装的唯一凭据。本机原先缺这个文件，于是界面把 pet 归到「自己写的 (1)」——那不是设计了一个分类，是来源凭据缺失导致的误判；现已补录标记（带 source: manual）归位到「从市场装的」。补录时还要给 backup.js 加离线兜底：带来源标记的模块原本备份只记名字、恢复靠市场重下，市场离线会丢模块。
  4. 分清两个生态：在 ~/.dsh/profiles/*/node_modules/ 里读 npm 包的版本与 repository，在 ~/.dsh/plugins-data/aurabot/modules/ 里读模块 module.json，别把应用插件列表里的开关当成 QQ 侧模块的开关。
  5. 清点目录而不是相信文案：逐个核对模块、客户端、素材包、Electron 运行时目录并数 webm 文件；这一步推翻过「Electron 未装」的旧结论。
  6. 读本机 README 与许可：分清作者仓库 / 设计来源 / 实际下载的包，别把 homepage 当成来源。
  7. 追配置的落点：从 post('/panel/pet/config') 追到 ext.pet.*，再追 ext.purpose.carrier，确认控制权在插件这一侧；载体开关现已收拢到桌宠卡，与目的机制卡写同一个值。

常见疑问 / 装到哪一步了

装了为什么桌面没东西？

分三层查：模块是否在跑（/panel/pet/status 的 module.running）、Electron 运行时是否装好（app/node_modules/electron/dist 里有没有 Electron.app）、进程有没有启动（面板「启动桌宠」）。模块在跑只代表接口通了，不代表窗口开了。

桌面那只蓝色鲸鱼怎么跟仓库里的角色不一样？为什么显示「离线」没有绿点？

蓝色 🐳 圆圈不是角色形象，是客户端还没拿到形象包时的占位图：app/index.html 里 1.5 秒没收到素材表就露出来，源码注释管它叫「桌宠变成了一个蓝色圆图标」。真正的形象是 packs/ 下 106 段 webm 动画的待机末帧（大肥鱼），本机素材齐全，客户端一连上宿主就会自动换，不用重装。

红点「桌宠离线」看的是桌宠客户端心跳——长轮询 /aurabot/api/events，60 秒没轮询就判离线；顶部绿点「在线」看的是 QQ 网关，两个状态源不同，所以不会一起变绿。两者常常同时出现：宿主端口漂移后客户端读到旧 host.json，窗口起来了但 /config、/asset/* 全连不上，于是既有占位图、又是离线。等端口注入完成后重新点「启动桌宠」即可。

第三方插件，开关为什么不在我这边？

其实一直在：开关都在 DSH 面板、值存在插件自己的 config.json。原先唯一分散的「主动搭话投递载体」也已收拢到桌宠卡，与目的机制卡是同一个值，不需要搬模块。

「已安装」页为什么写「自己写的 (1)」？

因为 modules/pet/ 缺 .aurabot-source.json（来源凭据）。本机已补录（标 source: manual），现在归到「从市场装的」。补录的同时给 backup.js 加了离线兜底：带来源标记的模块原本备份只记名字、恢复靠市场重下，市场离线时换电脑就会丢模块。

应用插件列表里的 dsh-pet 是这个吗？该开哪个？

不是同一个包。前者是 Harness 应用自己的 npm 插件 v0.3.8（用 43.3.0 的 Electron Helper），后者是 QQ 插件里的社区模块 v1.0.18（用 45.1.0 的 Electron 客户端），不共用进程和升级通道。想让 QQ 侧的「她」在桌面上陪你，用后者；别两边都开，会出两个桌宠。

我在插件市场里怎么升级？

Harness 侧：应用内「插件管理」找 dsh-pet，官方条目有新版本时点 Update（或 dsh plugin --profile desktop add dsh-pet@<版本> 重装）；没有独立 update 子命令。QQ 侧：市场默认离线，现在可以在「模块市场 → ① 模块索引地址」填 index.json 开启（也可设 QQSOUL_REGISTRY_URL），之后「可更新」里点一下就升级；不配索引也能手工替换 modules/pet/（模块热重载，不用重启 DSH）。

要不要做成内置模块？

管控层（面板、路由、配置）已经内置；不建议把模块本体连 Electron 客户端和 106 段素材塞进 src/modules/——包体积暴涨、会被升级覆盖、独立版本节奏也没了。更稳的是「内置适配层 + 数据目录里的独立模块」。

模块仓库里几十个模块，怎么在我这个项目里搜、装、升级？

上游有一套完整方案：registry 分支的 index.json（schema 1，44 个模块，带版本 / 分类 / 能力 / sha256 / 下载路径），CI 把每个模块打成 Release zip。本项目的「模块市场」页本来就实现了搜索、分类、安装、更新、卸载和 sha256 校验，只是默认离线、不预置上游地址。在「模块市场 → ① 模块索引地址」填一个索引地址即可开启，清空即回到离线，改完不用重启。详见 docs/flows/module-market.md。

macOS 弹「Electron 因为出现问题而无法打开」？

不是系统版本不兼容，是安装残缺：官方 macOS zip 里有 14 个 framework 符号链接，纯 JS 解压器把它们跳过了，dyld 找不到 Electron Framework。桌宠页首新增「修复 Electron」一键补回链接（不重下 115MB），/panel/pet/launch 启动前也会自动兜一次；Windows 官方包是扁平结构，不受影响。安装 Electron / 镜像 / 启停按钮已统一移到桌宠页最上面的「① 先装好，再启动」卡。

改了哪些地方要重启？

改 src/host.js 要重启 DSH，改 services/server.py（比如给课堂加课）要重启 9876 音频服务；数据目录里的模块与本地脚本是热重载的，不用重启。模块市场索引地址是例外：每次取索引都重算，面板保存后立刻生效。
