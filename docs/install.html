! 动手之前，先确认 3 件事

① 机器人号必须是小号主号拿去当机器人，你自己就没法正常用了。
② 别装上游 Aurabot两者挂载 ID、配置目录完全相同，会撞车、双份回复。
③ 安装包不带大模型默认说话走在线渠道，零下载；本地音色按需再装。

1 装插件

用本地目录安装 DSH

在 DSH 里选「本地目录安装」，指向这个项目文件夹，不要填 GitHub 地址。装完重启 DSH，左侧栏会出现「懂你的QQ大肥鱼」。

这一步不需要音频服务，也不需要开终端。

2 装 QQ 网关

让机器人号上线 QQ / 桌面端

  • macOS 用 NapCat，装在 QQ 里；扫码登录走它自己的 http://127.0.0.1:6099。
  • QQ 更新会覆盖 NapCat 的注入文件，更新后要重装一次。
  • Windows 用 SnowLuma 完整版（不是 lite），自己下载、自己点同意用户协议。
  • 解压到纯英文目录，例如 C:\qq-soul\snowluma。

关键是开「正向 WebSocket」：本机推荐 6700（NapCat 默认可能是 3001，以它实际监听的为准）。装回面板后，在「连接」页把地址填进去。

在哪点：桌面端「连接」页 →「本机服务（QQ / 网关 / 语音）」→「启动 QQ 与网关」。这一处就够了，不用再找第二个启动按钮。

3 起音频服务

声音和翻唱交给本机的 9876 服务 终端 / 桌面端

最简单：桌面端「概览」→「音频服务」卡片点「启动服务」。没起来时，在终端里跑下面这一行：

python3 -m services --serve

然后回桌面端「概览」，打开「启用音频服务」开关。

macOS / Linux 用 python3；Windows 用 python。

4 试一句、点一首

在桌面端确认能说能唱 桌面端

  • 「语音」页点一次试听；生成的文件路径会直接显示在卡片里，不用猜存哪了。
  • 「音乐源」卡片用「测试搜索」搜一首歌名，能搜出来就说明后面 AI 点歌也能搜。
  • 「翻唱」页点一首歌；进度、耗时、成品目录都能在网页大屏的「运行看盘」里看。
所有配置、导入、启停、点歌都在桌面端完成；网页大屏是只读看盘，两边读同一份数据。

5 跑一遍自检

五步全绿就能用了 桌面端 / 运维大屏

桌面端「连接」页的「连接体检」，或运维大屏「引导与原理 → 依赖体检」。看 service / deps / gateway / tts / song 五步。

有红的，把那一步的报错原文复制给 AI 就行。

? 卡住了？

DSH 每隔几分钟自己重启

多半是旧桥留下的守护进程在杀它。macOS 上检查 ~/Library/LaunchAgents/ 里有没有 com.merzlin.dsh-qq-supervisor.plist，有就移走。

面板显示「已就绪」，但 QQ 连不上

看网关 6700 有没有在听、插件有没有连上。桌面端「连接」页的「连接状态」会写清楚是没启动、没连上，还是登录的不是机器人号。

她一次回两条

NapCat 里还留着反向连 6700 的旧桥配置。删掉它，只保留正向 WebSocket。

网页大屏和桌面端看到的数不一样

两边读同一份配置，但分工不同：桌面端是唯一的写入口，网页只做日志、用量、作业进度、成品目录、模型库浏览。网页里的写按钮都被收起来了，看到「去桌面端」就回面板找对应卡片。
