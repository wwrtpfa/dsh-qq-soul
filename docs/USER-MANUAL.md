# 懂你的QQ大肥鱼 · 使用手册（给不懂技术的你）

> 大肥鱼住在 **DeepSeek Harness（DSH）** 里，QQ 是她的手机。DSH 你已经装好了，本手册不教装 DSH。
> 面板在 DSH 左侧栏「自动化任务」下面；另有一份**可双击打开**的运维大屏（`docs/prototype/index.html`）。
> 本产品以 MIT 协议的上游项目为基础二次开发，版权与许可见 `LICENSE` / `NOTICE.md` / `THIRD-PARTY-NOTICES.md`。

## 〇、三条必须先知道的事

1. **只装这一个插件，千万别和上游 Aurabot 同时装。** 两者挂载 ID、配置目录、preset ID 完全相同，同时装会撞车、出现**双份回复**。首次设置向导会自动检测并给出卸载命令。
2. **机器人号一定用小号**，主号不要拿来当机器人。
3. **安装包不带任何大模型**。默认说话走微软在线（零下载）；要本地音色或唱歌，才按需下载，面板只给链接和「选目录加载」。

## 一、10 分钟跑通（最短路径）

| 步 | 做什么 | 在哪 |
|---|---|---|
| 1 | 装插件：`dsh plugin --profile desktop add <本仓库目录>`（Web 端换 `--profile web`） | 终端 |
| 2 | 装完重启 DSH，左侧栏打开面板，走完 5 步设置向导 | 面板 |
| 3 | 装好并**自己启动** QQ 网关，把它的**正向 WebSocket** 地址填进「连接」页 | 见第二节 |
| 4 | 起音频服务：`python3 -m services --check-deps`，再 `python3 -m services --serve` | 终端 |
| 5 | 打开运维大屏（双击 HTML，或访问 `http://127.0.0.1:9876/panel`），点「连接 service」 | 浏览器 |
| 6 | 点「跑一遍自检」，看五步是不是全绿 | 大屏 |

第 4~6 步只影响**说话和唱歌**；不装音频服务，聊天、记忆、人格照常能用。

> 开发期注意：改了代码要重新跑一遍安装命令并重启 DSH，否则跑的还是旧副本。

## 二、接 QQ 网关（唯一必须自己动手的地方）

本插件是 **OneBot v11 正向 WebSocket 客户端**：它主动去连你启动的网关，**不监听端口、不启动网关、不给 QQ 注入任何东西**。

### macOS（推荐 NapCat）

**最短路径：面板「连接」页 →「连接体检」→ 点「一键修复并启动」。** 它会检查七行（QQ 装没装、NapCat 在不在、WebSocket 方向对不对、插件地址填没填、端口通不通……），缺什么写什么，能补的直接补：把 NapCat 改成**正向 WebSocket 服务端**（默认 6700）、关掉指向同一端口的旧反向连接、回填插件地址、再帮你启动 QQ。修完还是红，就按每行后面的「→」手动做。

手动做法：

1. 自己装好并启动 NapCat / LLOneBot / Lagrange，登录机器人小号。
2. 在网关里打开**正向 WebSocket 服务**（本机推荐 `ws://127.0.0.1:6700`，一键修复会自动配成这个端口；NapCat 自己默认可能是 3001，以它实际监听的端口为准），有 `access_token` 就一并填进面板。
3. 面板「连接」页选 **「接我已有的 OneBot 机器人」**，填地址 → 保存 → 等状态变成「已连上」。插件会自动核对登录的是不是你填的机器人号，不是就断开。

> ⚠️ **方向别搞反**：插件是客户端，网关必须是**服务端**。NapCat 里只留 `websocketClients`（反向连 6700）而没开 `websocketServers` 时，两边都在当客户端，**没人监听**，谁都连不上——这也是「DSH 反复重启」的旧根因（见第七节）。

> ⚠️ **从旧桥迁过来的人**：如果 NapCat 里还留着 `websocketClients` 反向连 `ws://127.0.0.1:6700`，**一定要关掉或删掉**。同一个 QQ 号被旧桥和本插件两个消费者抢答，表现就是「她一次回两条」。大屏五步自检的第 3 步会检查这个残留。

### Windows（SnowLuma 完整版）

1. 自己下载 **SnowLuma 完整版 zip（不带 lite）**——它的协议不允许程序替你自动部署。
2. 解压到纯英文目录（例如 `C:\qq-soul\snowluma`），目录里能直接看到 `index.mjs`。
3. 面板里填目录 → 启动 → 本人阅读并勾选**同意 EULA** → 接入机器人号。
4. 控制台密码由插件自动生成并保存，不用自己记；之前手动设过密码就点「重置为自动密码」。

## 三、音频服务 9876（说话 / 唱歌）

服务是随插件分发的 Python 包，**零第三方依赖**（标准库 `http.server`），只监听 `127.0.0.1:9876`。

```bash
python3 -m services --check-deps          # 依赖体检，只查不装
python3 -m services --serve               # 起服务
python3 -m services --once --text "你好呀" # 不启后台，直接读一句
python3 -m services --stub --serve        # 没模型也能自检整条 HTTP 契约
```

> **Windows** 把 `python3` 换成 `python`，并且要在**插件仓库目录**里运行。记不住路径也没关系：面板「概览 → 音频服务」会给出带完整目录的命令，点「复制」即可。服务的配置、模型和翻唱缓存放在 `~/.dsh/plugins-data/qqsoul/service/`（Windows 是 `%USERPROFILE%\.dsh\plugins-data\qqsoul\service\`）。

- **默认零下载**：edge-tts（微软在线）说一句就成，不用任何权重。
- **可选本地**：GPT-SoVITS、千问 3-TTS MLX（仅 Mac）、Breeze 远程、任意 HTTP TTS。长文本自动**分句合成 + 静音拼接**，不会撕裂音。
- **面板**：`http://127.0.0.1:9876/panel`，或直接双击 `docs/prototype/index.html`（已允许 `file://` 直连）。默认演示模式，点「连接 service」后所有表格只读真实推送，**不替服务端造状态**。

### 五步自检

| 步 | 检查什么 | 没过怎么办 |
|---|---|---|
| 1 | 音频服务 9876 | 看上面的启动命令 |
| 2 | 依赖体检（必需项） | 每项都带一句人话修复动作，照着做 |
| 3 | QQ 网关正向 WS | 确认 NapCat 已启动、地址是 `ws://`、没有 6700 旧桥残留、登录号对得上 |
| 4 | 读一句话 | 会真合成一句探针音，去「语音渠道」页看渠道配置 |
| 5 | 唱一首歌 | 默认只验链路可达（快）；点「深度自检」才真跑一首 |

每一步都返回**可枚举的 code + 一句人话**；大屏只转述，不让你猜日志。

## 四、模型：三档分发、四态管理

| 档 | 内容 | 下载量 |
|---|---|---|
| 零下载默认 | edge-tts / Breeze 远程（只填 key） | 0 |
| 按需轻量 | ffmpeg、分离权重、contentvec / rmvpe | 给链接，点了才下 |
| 纯手动导入 | GPT-SoVITS 整包、千问 MLX、RVC `.pth` + `.index` | 只给链接 + sha256 + 选目录加载 |

模型管理页四态：**未安装 / 已下载待加载 / 已加载 / 路径失效**。按钮是 `复制链接 → 自己下好并校验 → 拖进来 → 选目录加载 → 立即释放`。
选过的路径会写进 `config.json` 并**立即生效**，下次启动直接用；换策略也不会命中旧成品（策略指纹进了曲库缓存键）。

## 五、唱歌的几个旋钮

在面板「翻唱」页，保存后下一首立即生效：

1. **演唱模式（三选一）**：清唱（只发人声）/ 伴奏·去前奏空白（从人声第一句开始）/ 伴奏·保留前奏（完整前奏）。点歌请求里带了模式就以请求为准，没带才用后台保存的默认值。
2. **人声分离**：默认 `demucs htdemucs`；`BS-RoFormer` 是慢 4–6 倍的高质量离线档，没配命令会明确报「未配置」，不假装支持。
3. **前奏处理**：自动裁剪 / 固定裁 N 秒 / 保留不裁。自动档在**分离后的 vocals 轨**上算自适应 RMS 起唱点；「伴奏·保留前奏」模式会强制不裁。
4. **取窗策略**：整首 / 固定起点+时长。填好「从哪里开始唱」和「唱多久」，面板会直接告诉这一首实际唱多长，不用再猜。
5. **混音音量**：人声 / 伴奏音量、混响、高频修正；桌面面板和大屏读到的是同一份 service 配置。
6. **推理驻留**：常驻省冷启动，空闲 8 分钟自动卸载；`index_rate`、`pitch` 每首可调。

> 裁剪只在分离后的唯一入口做一次，人声、伴奏、混音吃同一组起点和时长，**不会错位**。作业日志里能看到能量曲线缩略图和每阶段耗时。

### 音乐源与缓存

翻唱页的「音乐源」只有**两个聚合站**：`txqq`（music.txqq.pro）和 `music-dl`（music.zkkp.nyc.mn）。按列表从上往下搜，每个站取前 10 首，再按顺序挑第一首真能下到音频的。两个站都搜不到，会在聊天里明确回一句「这首歌不存在 / 没唱成 + 原因」，不会再已读不回，也不会绕回会员平台。

- 试唱时可以选站：桌面面板和运维大屏的「搜哪个站」下拉，读的是同一份列表，每个站最多取 10 首。
- 搜歌和下载是两条独立的工具（`qq_music_search` / `qq_music_download`）：只搜不下也行，下好的文件也能直接交给 `qq_song_cover` 唱。
- 加站：点「添加站」只能选 `txqq` 或 `music-dl`；地址留空用内置地址。
- 排序：列表从上到下就是搜索顺序，用 ↑ / ↓ 调；关掉某一行的开关就跳过它。
- 恢复：改乱了点「恢复默认」，回到 txqq + music-dl。
- **music-dl 的说明**：zkkp 站点挂了腾讯云 EdgeOne 人机验证，脚本（没有浏览器 cookie）请求搜索页和下载页只会拿到验证页。这里不绕过验证：自动搜时会跳过它，并把「需要浏览器验证」写进诊断。想让它自动可用，就在本机跑一个 go-music-dl（没有 EdgeOne），把该行的地址填成 `http://127.0.0.1:<端口>`。

下载过的原曲和成品会留在服务数据目录，下一次点同一首歌直接命中缓存，不再重复下载：

| 目录 | 放什么 |
|---|---|
| `music/originals/` | 下载的原曲 |
| `music/covers/` | 翻唱成品 |
| `music/work/` | 分离 / 转换的中间产物（可清） |

翻唱页会直接显示这几个目录的完整路径和「复制」。想省磁盘，清 `work/` 最安全；`covers/` 删了只是下次重唱，`originals/` 删了下次重新下载。

成品文件名一眼能认：`歌名-歌手-音色-清唱|伴奏-日期`，不再是歌名后面挂一串随机 ID。同一首歌、同一个音色、同样的清唱/伴奏和取窗策略已经做过，再点一次会**直接放曲库里的那一版**，不再重跑几分钟；换了音色、模式或起点/时长才会重新做。两个面板的「已翻唱」列表都能直接试听（可暂停）和删除成品。

## 六、日常怎么用

- 在 QQ 里直接和她聊；私聊能用的工具比群里多。
- `/sing 歌名` 点歌、语音条开关在「语音」页；具体命令清单在面板「命令」页。
- 点歌失败会**在聊天里回一句人话**：搜不到 / 没版权 / 要会员 / 缺模型都会说清楚，不会再默默消失。换一首、或在翻唱页「音乐源」里换一个站再试。
- 想让她多会点什么：面板「工具 / 技能」页把模块按**代码工具**和**知识技能**两组分别开关；也可以往 `skills/` 目录放 Markdown 技能文件（frontmatter 写 `name` / `description` / `triggers` / `permissions`，权限只允许 `read` 和 `llm`）。
- 「运维大屏」是独立的全屏报告页，可分享给朋友看：Token 消耗、统一时间线（**7 天、含正文**）、驻留 worker、作业进度都在那儿。

## 七、出问题先看这里

| 现象 | 先看什么 |
|---|---|
| **DSH 每隔几分钟自己重启** | 不是插件崩了。旧项目的「桥守护」（`pet.ops.supervisor`，LaunchAgent `com.merzlin.dsh-qq-supervisor` 或 9890 控制台里的后台线程）把「6700 没监听」当成「桥死了」，于是 `kill -9` 再拉起。本插件不再监听 6700，这个判据永远不成立 → 关掉守护：`touch /tmp/dsh-qq-supervisor.pause`，并把 LaunchAgent 移出 `~/Library/LaunchAgents`。控制台脚本已默认不启动守护（要旧行为用 `QQ_GUARD=1`） |
| 面板显示「已就绪」但 QQ 没连上 | 顶部胶囊只说总开关状态，具体原因看它下面那行红字（或「连接」页的「连接体检」）。常见是网关方向反了 / QQ 没开 |
| 一次回两条 | 上游插件没卸干净，或 NapCat 还反向连 6700；向导和大屏自检都会提示 |
| 连不上网关 | 网关是不是**你自己启动**的；地址是不是 `ws://` / `wss://`；token 对不对；Docker 里别填 `127.0.0.1` |
| 面板打不开 service | 先跑 `python3 -m services --check-deps`（Windows 用 `python`），再看 9876 有没有被占用、token 有没有填；也可以直接在面板「概览 → 音频服务」点「测试连接」，那里有带本机目录的启动命令 |
| 改了代码不生效 | 重新跑安装命令并重启 DSH（开发期常见坑） |
| 翻唱报「缺模型 / 路径失效」 | 模型页重新选目录加载，路径已持久化但文件可能被挪走 |
| 自检第 3 步红 | 插件还没上报网关状态：确认「连接」页已连上、service 客户端开关已打开 |
| 换电脑 | 面板「系统 → 备份」导出 zip，新电脑装好 DSH 与**本插件**后拖进同一页恢复；数据目录以外的路径（ffmpeg、模型目录）要重新填 |

数据分两处：

| 位置 | 放什么 |
|---|---|
| `~/.dsh/plugins-data/aurabot/` | 插件自己的配置、人格、表情、日记、记忆、日志、你的模块（内部目录名沿用上游，只为兼容老配置，**不代表品牌归属**） |
| `~/.dsh/plugins-data/qqsoul/service/` | 音频服务的配置、模型路径、翻唱缓存和作业日志（`config.json` 里有接口密钥，别发给别人） |

换电脑时，面板「系统 → 备份」只打包前一处；音频服务的模型和翻唱缓存建议按需重新下载 / 重唱，`config.json` 里的渠道密钥重新填一次更安全。
作业日志在服务数据目录的 `jobs/*.jsonl`；音频成品在 `audio/`；Token 与时间线在 `ops/`。

## 八、账号安全

- 机器人一定用小号。用 NapCat / SnowLuma 这类非官方工具有被限制或封号的风险，主号别拿来当机器人。
- 面板默认只有本机能打开；要远端管理必须显式打开，并务必在反向代理层再加一道认证。
- 备份包里有账号凭证，别发给别人。
