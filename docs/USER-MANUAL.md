## 〇、三条必须先知道的事

1. **只装这一个插件，千万别和上游 Aurabot 同时装。** 两者挂载 ID、配置目录、preset ID 完全相同，同时装会撞车、出现**双份回复**。首次设置向导会自动检测并给出卸载命令。
2. **机器人号一定用小号**，主号不要拿来当机器人。
3. **安装包不带任何大模型**。默认说话走微软在线（零下载）；要本地音色或唱歌，才按需下载，面板只给链接和「选目录加载」。

## 二、接 QQ 网关（唯一必须自己动手的地方）

本插件是 **OneBot v11 正向 WebSocket 客户端**：它主动去连你启动的网关，**不监听端口、也不替网关注入 QQ**。面板里的「启动 QQ 与网关」按钮只是把本机现成的 QQ 网关启动脚本调起来（Windows 调 NapCat 启动器，macOS 调 LaunchServices），注入、登录都由网关自己完成；插件也不会替你关 QQ。

### macOS（推荐 NapCat）

**最短路径：面板「连接」页 →「连接体检」→ 点「一键修复并启动」。** 它会检查七行（QQ 装没装、NapCat 在不在、WebSocket 方向对不对、插件地址填没填、端口通不通……），缺什么写什么，能补的直接补：把 NapCat 改成**正向 WebSocket 服务端**（默认 6700）、关掉指向同一端口的旧反向连接、回填插件地址、再帮你启动 QQ。修完还是红，就按每行后面的「→」手动做。

手动做法：

1. 自己装好并启动 NapCat / LLOneBot / Lagrange，登录机器人小号。
2. 在网关里打开**正向 WebSocket 服务**（本机推荐 `ws://127.0.0.1:6700`，一键修复会自动配成这个端口；NapCat 自己默认可能是 3001，以它实际监听的端口为准），有 `access_token` 就一并填进面板。
3. 面板「连接」页选 **「接我已有的 OneBot 机器人」**，填地址 → 保存 → 等状态变成「已连上」。插件会自动核对登录的是不是你填的机器人号，不是就断开。

> ⚠️ **方向别搞反**：插件是客户端，网关必须是**服务端**。NapCat 里只留 `websocketClients`（反向连 6700）而没开 `websocketServers` 时，两边都在当客户端，**没人监听**，谁都连不上——这也是「DSH 反复重启」的旧根因（见第七节）。

> ⚠️ **从旧桥迁过来的人**：如果 NapCat 里还留着 `websocketClients` 反向连 `ws://127.0.0.1:6700`，**一定要关掉或删掉**。同一个 QQ 号被旧桥和本插件两个消费者抢答，表现就是「她一次回两条」。大屏五步自检的第 3 步会检查这个残留。

### Windows（NapCat，本机已装好时最省事）

1. 面板「连接」页 →「本机服务」或「连接体检」→ 点 **「启动 QQ 与网关」**（两处是同一个动作，点一次就够）。Windows 上这个按钮会找 NapCat.Shell 官方入口 **`napcat.bat`**，并自动带上 `-q <机器人号>` 复用本机登录态，**不用每次扫码**。找不到它才依次退回 `start-napcat.bat`、`launcher-*.bat`、`NapCatWinBootMain.exe` 注入器。
2. 「连接体检」里会写出这次实际调用了哪个文件；要换脚本可设环境变量 `QQSOUL_QQ_LAUNCHER`（完整路径），NapCat 装在别处可设 `QQSOUL_NAPCAT_DIR`，换号改 `QQSOUL_QQ_ACCOUNT`。
3. **双击 `启动QQ-NapCat.bat` 更省事**：一次完成「`napcat.bat -q` 快速登录 → 等 6099 起来 → 自动打开 WebUI 登录页」。NapCat 在独立的最小化窗口里常驻。
4. **WebUI**：`http://127.0.0.1:6099/webui/web_login`；带 token 的管理面板 `http://127.0.0.1:6099/webui/?token=<webui.json 里的 token>`。端口 6099、6700、6701 都起来才算就绪。
5. NapCat 要开**正向 WebSocket 服务端**（本机 `ws://127.0.0.1:6700`，HTTP 接口 6701）。「一键修复并启动」会备份后改好 NapCat 配置并回填插件地址。
6. 网关端口 6700 已经在监听时，按钮会提示「不用重复启动」——NapCat.Shell 不产生 `QQ.exe` 进程，所以按端口判断，不按进程判断。退出 QQ 请自己在 QQ / WebUI 里操作，插件不会代你关。

> ⚠️ 本机实测 `start-napcat.bat`（`NapCatWinBootMain.exe` 注入器）在这台机器上带不起 6099/6700，所以按钮与一键脚本都改用官方 `napcat.bat`。若 `-q` 快速登录失效（登录态过期），去掉 `-q` 用 WebUI 扫码一次即可。

> 「本机服务」卡片里的三个「高级」按钮（按当前引擎启动 / 只重启桥 / 全部停止）管的是本机语音组件，日常不用碰；音频服务没开时它们不可用，但「启动 QQ 与网关」照常能点。

### Windows（SnowLuma 完整版）

1. 自己下载 **SnowLuma 完整版 zip（不带 lite）**——它的协议不允许程序替你自动部署。
2. 解压到纯英文目录（例如 `C:\qq-soul\snowluma`），目录里能直接看到 `index.mjs`。
3. 面板里填目录 → 启动 → 本人阅读并勾选**同意 EULA** → 接入机器人号。
4. 控制台密码由插件自动生成并保存，不用自己记；之前手动设过密码就点「重置为自动密码」。

## 三、音频服务 9876（说话 / 唱歌）

服务是随插件分发的 Python 包，**零第三方依赖**（标准库 `http.server`），只监听 `127.0.0.1:9876`。

```bash
# Windows（先 cd /d 到插件目录）
python -m services --check-deps          # 依赖体检，只查不装
python -m services --serve               # 起服务
python -m services --once --text "你好呀" # 不启后台，直接读一句
python -m services --stub --serve        # 没模型也能自检整条 HTTP 契约

# macOS / Linux：把上面的 python 换成 python3
```

> **macOS / Linux** 把 `python` 换成 `python3`，并且要在**插件仓库目录**里运行。记不住路径也没关系：面板「概览 → 音频服务」会给出带完整目录的命令，点「复制」即可。服务的配置、模型和翻唱缓存放在 `~/.dsh/plugins-data/qqsoul/service/`（Windows 是 `%USERPROFILE%\.dsh\plugins-data\qqsoul\service\`）。

- **默认零下载**：edge-tts（微软在线）说一句就成，不用任何权重。
- **可选本地**：GPT-SoVITS、千问 3-TTS（Mac 用 MLX 本地模型；Windows 连本机 `9883` 常驻服务）、Breeze 远程、任意 HTTP TTS。长文本自动**分句合成 + 静音拼接**，不会撕裂音。
- **面板**：`http://127.0.0.1:9876/panel`，或直接双击 `docs/prototype/index.html`（已允许 `file://` 直连）。默认演示模式，点「连接 service」后所有表格只读真实推送，**不替服务端造状态**。

#### Windows 用户：说话 / 唱歌各走哪条

Windows 上也可以用**快速 RVC**（`rvc_convert.py` + `infer/`）或 Applio，服务按目录里实际有的文件自动选后端；不管用哪套，说话和唱歌都是同一个声音：

| 用途 | 怎么配 | 说明 |
|---|---|---|
| 说话 | 「语音」页选渠道 | 默认 `edge`（在线、零下载、秒级）；要本地音色就切 `gptsovits`，连你自己起的服务 |
| 唱歌 / 语音条变声 | 「翻唱」页一键安装，或指向已有环境 | 有 NVIDIA 独显走 CUDA 会快很多，没有也能用 CPU 跑 |
| 唱歌音色 | 「翻唱 → 音色模型」导入 `.pth` + `.index` | 说话、唱歌、试听共用同一个音色 |
| 网关启动 | 面板「启动 QQ 与网关」 | 用 NapCat 正向 WS；别同时保留旧桥的反向 WS 6700 |

**GPT-SoVITS 启动脚本注意**：默认 `tts_infer.yaml` 是 `cuda + is_half`，老整合包自带的 torch 可能不认新显卡（例如 RTX 50 系），会退化成一句几十秒甚至更久。换成 CPU 配置（`-c GPT_SoVITS/configs/tts_infer.cpu.yaml`）通常能跑通，首句冷加载约 70 秒属正常。

**渠道下拉里怎么选**：`gptsovits` 需要你的 GPT-SoVITS 服务在跑；没起时选它会被拦下并给出一句能照做的提示（不会把配置写坏）。`qwen` 两个平台都能用，但**走的路不一样**：macOS 是 MLX 本地模型（在「模型目录」里选目录加载），Windows 是连本机的 TTS 服务（不用 MLX，也不用选模型目录）。

### 声音这一页怎么配（说话换声 / 变调 / 备用渠道）

这一页以前最难懂，现在按「从上到下就是一条链路」来读：

1. **说话渠道**：选谁说话。**选完之后，这个渠道自己的参数就紧跟在它下面**——Breeze 是「服务地址 + Token」，GPT-SoVITS 是「参考音频」，千问是「服务地址 + 模型目录」。不用再滚到别的卡片去找。改完点这一组右边的「保存渠道参数」，下一句就生效。
2. **换声（说话和唱歌同一个声音）**：一个开关管两条链路。
   - **说话换声**：开着，说出来的每句话都会换成你选的那个音色；关掉就用渠道自己的原声。
   - **换声音色**：选 `.pth` + `.index`。说话、唱歌、试听用的是**同一个音色**，不会出现「唱是一个声、说是另一个声」。
   - **变调**：**只有一个数**，说话换声和唱歌共用它。`0` = 不变调，`+4` = 升 4 个半音，`-4` = 降 4 个半音。以前面板上的变调只写给唱歌那条路，说话根本不看——现在改一次两边都变，保存后**下一句 / 下一首**生效。
3. **本机备用渠道**（默认展开、默认开着）：音频服务连不上或者合成失败时，自动改用这一套（引擎 / 音色 / 语速 / 变调）。
   - 开着：服务挂了也不至于没声音，只是换成本机这套声音。
   - 关掉：服务不行就直接**改发文字**，不会偷偷换成一个不一样的声音。想要「要么原声、要么不说话」就关掉它。
4. **混音与清唱**：只有一组参数（人声音量、伴奏音量、混响、高频、响度）。
   **「清唱」不是一个额外开关**——把伴奏音量拉到 0 就是清唱，卡片上会直接显示「当前效果：清唱（只有人声）」。

> 这一页所有卡片都是**改完点保存才写进去**，没保存会有「已改动」标记和「撤销」。不存在「点一下就已经写盘、但不知道什么时候生效」的情况。

**试听的文件到底存哪**：只有一个「语音试听」目录，面板里显示的那条路径就是文件真正所在。音频服务开着时它是服务的 `audio/`（和只读大屏的「试听目录」是同一份），服务关着才是插件自己的 `audio/`；面板「目录与路径 → 语音试听输出」里手填的路径优先级最高。点完「生成」，下面会写出文件名、所在目录，旁边两个按钮：**打开文件夹**（直接在 Finder / 资源管理器里翻出来）和**复制路径**。

## 四、模型：三档分发、四态管理

| 档 | 内容 | 下载量 |
|---|---|---|
| 零下载默认 | edge-tts / Breeze 远程（只填 key） | 0 |
| 按需轻量 | ffmpeg、分离权重、contentvec / rmvpe | 给链接，点了才下 |
| 纯手动导入 | GPT-SoVITS 整包、千问 MLX、RVC `.pth` + `.index` | 只给链接 + sha256 + 选目录加载 |

模型管理页四态：**未安装 / 已下载待加载 / 已加载 / 路径失效**。按钮是 `复制链接 → 自己下好并校验 → 拖进来 → 选目录加载 → 立即释放`。
选过的路径会写进 `config.json` 并**立即生效**，下次启动直接用；换策略也不会命中旧成品（策略指纹进了曲库缓存键）。

## 五、唱歌的几个旋钮

面板「翻唱」页里这张卡叫**「怎么唱」**，只有**两个维度**，其余是音质细节。保存后下一首立即生效：

1. **演唱模式（三选一）**——伴奏怎么处理，连前奏和间奏一起定：
   - **清唱**：整首只发人声。前奏、间奏、结尾的伴奏**全部去掉**（不是只把前奏切掉）。
   - **伴奏 · 去前奏**：从人声第一句开始，开头那段纯伴奏切掉；之后伴奏一直在（间奏也保留）。
   - **伴奏 · 保留前奏**：原曲开头也留着，适合前奏本身好听的歌。

   点歌请求里带了模式就以请求为准，没带才用后台保存的默认值。
2. **唱多长（二选一）**：**整首**，或**只唱一段**（填「从哪里开始唱」和「唱多久」，面板会告诉你这一首实际唱多长）。原曲不够长就唱到结尾。
3. **起唱点怎么定**：只在「伴奏 · 去前奏」时出现——自动找人声起点（在分离后的 vocals 轨上算自适应 RMS），或固定裁掉开头 N 秒。选「清唱 / 保留前奏」时这一项不出现，也不会跟前面对打。
4. **人声分离**：默认 `demucs htdemucs`；`BS-RoFormer` 是慢 4–6 倍的高质量离线档，没配命令会明确报「未配置」，不假装支持。
5. **混音（另一张卡）**：人声 / 伴奏音量、混响、高频修正。这张卡里**没有**「清唱开关」——要整首没伴奏请回上面选「清唱」，这里只是把伴奏调小。桌面面板和大屏读到的是同一份 service 配置。
6. **推理驻留**：常驻省冷启动，空闲 8 分钟自动卸载；`index_rate`、`pitch` 每首可调。
   这里的 `pitch` 和「声音」页的**变调是同一个值**——在哪儿改都一样，说话和唱歌一起变。

> 「声音」卡里的**「QQ 语音条最长」**是另一回事：它管的是发到 QQ 的语音条截多长，跟翻唱成品「唱多长」不是同一个设置。

> 裁剪只在分离后的唯一入口做一次，人声、伴奏、混音吃同一组起点和时长，**不会错位**。作业日志里能看到能量曲线缩略图和每阶段耗时。

### 音乐源与缓存

翻唱页的「音乐源」只有**两个聚合站**：`txqq`（music.txqq.pro）和 `music-dl`（music.zkkp.nyc.mn）。按列表从上往下搜，每个站取前 10 首，再按顺序挑第一首真能下到音频的。两个站都搜不到，会在聊天里明确回一句「这首歌不存在 / 没唱成 + 原因」，不会再已读不回，也不会绕回会员平台。

- 试唱时可以选站：桌面面板和运维大屏的「搜哪个站」下拉，读的是同一份列表，每个站最多取 10 首。
- 搜歌和下载是两条独立的工具（`qq_music_search` / `qq_music_download`）：只搜不下也行，下好的文件也能直接交给 `qq_song_cover` 唱。
- 加站：点「添加站」只能选 `txqq` 或 `music-dl`；地址留空用内置地址。
- 排序：列表从上到下就是搜索顺序，用 ↑ / ↓ 调；关掉某一行的开关就跳过它。
- 恢复：改乱了点「恢复默认」，回到 txqq + music-dl。
- **music-dl 的说明**：zkkp 站点挂了腾讯云 EdgeOne 人机验证，脚本（没有浏览器 cookie）请求搜索页和下载页只会拿到验证页。这里不绕过验证：自动搜时会跳过它，并把「需要浏览器验证」写进诊断。想让它自动可用，就在本机跑一个 go-music-dl（没有 EdgeOne），把该行的地址填成 `http://127.0.0.1:<端口>`。

下载过的原曲和成品会留在服务数据目录，下一次点同一首歌直接命中缓存，不再重复下载：

| 目录 | 放什么 |
|---|---|
| `music/originals/` | 下载的原曲 |
| `music/covers/` | 翻唱成品 |
| `music/work/` | 分离 / 转换的中间产物（可清） |

翻唱页会直接显示这几个目录的完整路径和「复制」。想省磁盘，清 `work/` 最安全；`covers/` 删了只是下次重唱，`originals/` 删了下次重新下载。

成品文件名一眼能认：`歌名-歌手-音色-清唱|伴奏-日期`，不再是歌名后面挂一串随机 ID。同一首歌、同一个音色、同样的清唱/伴奏和取窗策略已经做过，再点一次会**直接放曲库里的那一版**，不再重跑几分钟；换了音色、模式或起点/时长才会重新做。两个面板的「已翻唱」列表都能直接试听（可暂停）和删除成品。

## 六、日常怎么用

- 在 QQ 里直接和她聊；私聊能用的工具比群里多。
- `/sing 歌名` 点歌、语音条开关在「语音」页；具体命令清单在面板「命令」页。
- 点歌失败会**在聊天里回一句人话**：搜不到 / 没版权 / 要会员 / 缺模型都会说清楚，不会再默默消失。换一首、或在翻唱页「音乐源」里换一个站再试。
- 想让她多会点什么：面板「工具 / 技能」页把模块按**代码工具**和**知识技能**两组分别开关；也可以往 `skills/` 目录放 Markdown 技能文件（frontmatter 写 `name` / `description` / `triggers` / `permissions`，权限只允许 `read` 和 `llm`）。
- 「运维大屏」是独立的全屏报告页，可分享给朋友看：Token 消耗、统一时间线（**7 天、含正文**）、驻留 worker、作业进度都在那儿。

### 人格（人设）怎么开、怎么关

人格就是**一段提示词**，没别的东西。人格可以有多个，但**一次只启用一个**。面板「人设」页左边是人格列表：

- 每张人格卡片上都有一个**启用开关**。点一下就是切换：开 B 就等于「从 A 换到 B」，不用先关 A。
- **关掉当前这个** = 这个人格整段提示词**都不发给模型**，只剩规则和上下文。适合「只想让她正常回话、不要演」的时候。
- 卡片上的标记会跟着变：**正在用** / **已停用** / **未保存**（新建但还没保存的，左边会先出现一条，保存后才真正写盘）。
- 每节还有自己的「用于上下文」开关——那个管的是**只关某一节**，整段关掉时所有节都不发。

开关是**点了立刻动**的（不用等保存），但只有点「保存」才真的写进配置；底部的状态行会提示还有没有没保存的改动。

### 让ta画图（生图）怎么接

面板「表达 → 生图」页，接口只有两种，**不用再理解「本地 api-image」那套**：

1. **自定义接口**（绝大多数人用这个）：三格填完就能用 —— **接口地址**（填到 `/v1` 为止）、**API Key**、**模型**。任何 OpenAI 兼容的生图服务都行：官方 OpenAI、硅基流动、通义万相兼容层、自建中转、本机 ComfyUI / SD WebUI 的 OpenAI 代理。
   - **API Key 默认是打码的**（一串圆点），旁边有「显示」——想核对有没有粘错就点一下，看完再点「隐藏」。它只存在本机配置里。
   - **模型**由你自己填服务商给的名字；留空或填 `auto` 会依次试几个常见名字。
   - **接口地址留空** = 用本机 Codex 配置（`~/.codex/config.toml`）里那一份。不想手抄就点「本机 Codex 配置 → 填入」，它会把地址和密钥一次填进上面三格。
2. **自定义接口 → URL 模板**：接口不是 OpenAI 那种（比如 pollinations：GET 一个地址就出图），就在「接口地址」里写模板，`{prompt}` 会被替换成提示词，参数自己加。
3. **Codex 订阅（实验性）**：登录 ChatGPT 账号用订阅额度，可用性由账号和服务端决定。

填完打开右上角开关、保存，然后在「测试生图」里点一下就能当场看到结果（不发 QQ、不进图库）。

- **构图**里有一档「**不指定（按提示词来）**」：选它**一个尺寸参数都不发**，交给接口和提示词自己决定。有些服务收到不认识的 `size` 直接 400，就用这一档。
- 「测试生图」卡里会显示**测试图目录**（`imagegen/test/`）和一个「打开文件夹」：每次测的画都顺手存一份，方便回头对比。它和「她的画作」图库是分开的 —— 图库只收真正发出去的画。

### 本机模型在哪、装了什么

面板「语音」页有一张**「本机模型」**卡：千问 3-TTS、GPT-SoVITS、RVC 音色、人声分离 htdemucs 四个引擎各占一行，写着

- 现在用的是哪个目录（**自动找到**的会标出来，不用你填）、占用多大；
- 没配的会写「还没选」；
- 每行都有「**选目录**」和「**打开文件夹**」——想看看权重到底躺在哪，直接点开就行。

所有模型都放在音频服务的 `models/` 下面（卡片顶部会写出完整路径），换机器整个目录搬走即可。

**RVC 音色只认一个库**（音频服务的 `models/rvc/`）。本机老目录（`~/tools/models`、`~/models`）里扫到的音色也会列出来，但会标「**不在音色库**」，旁边有「**收进音色库**」；卡片顶上还有一个「全部收进来」。搬进去之后改名 / 删除 / 换声都只有一处，不会出现「同一个音色两个入口、选哪个还各不一样」。搬的时候如果配置正指着那个文件，路径会自动改到新位置。

### Token 花了多少钱

面板「运行记录」页（现在叫**「用量与花费」**）除了 token 数，还会直接给**金额**：今天花了 ¥x.xx、最近 7 天累计，外加**缓存命中率**，每天一行也带金额。

- 单价分**三档**（元 / 百万 token）：**命中缓存的输入**、**未命中的输入**、**输出**。命中缓存比未命中便宜两个数量级 —— 以前按「输入全价」估，一天能算成几十块，就是这个原因。
- 命中多少 token 是**真数**：DSH 的 `cacheReadTokens`（OpenAI 兼容层是 `prompt_tokens_details.cached_tokens`）读得到就用它；读不到就从总数里减（`总数 − 未命中输入 − 输出`）。
- **峰时自动 ×2**，你填的法定节假日按谷时算（峰谷规则和「峰谷省钱」那张卡一致）。
- 单价在「模型 → **峰谷与金额**」里改：预设 `deepseek-flash` / `deepseek-v4-pro`，或点「自定义」自己填三档。改完金额立刻按新价重算。
- 同一份统计**打开页面算一次**：日志文件没变就复用上次结果，不是每次渲染都重算。
- 老记录（升级前写的、没存命中数）只能按 3:1 粗估，页面上会写「有 N 轮是旧记录……偏高于实际」。
- 今日收到 / 发出 / 语音 / 表情这几个数**会落盘**（`data/stats.json`），重启 DSH 或插件不会清零，跨天自动归零。

## 七、出问题先看这里

| 现象 | 先看什么 |
|---|---|
| **DSH 每隔几分钟自己重启** | 不是插件崩了。旧项目的「桥守护」（macOS：`pet.ops.supervisor`，LaunchAgent `com.merzlin.dsh-qq-supervisor`；Windows：旧桥 `dsh-qq-onebot-bridge` 或计划任务）把「6700 没监听」当成「桥死了」反复拉起。本插件不再监听 6700，这个判据永远不成立 → macOS 关掉守护（`touch /tmp/dsh-qq-supervisor.pause`，并把 LaunchAgent 移出 `~/Library/LaunchAgents`）；Windows 把旧桥从 profile 的 bundles 移除并设 `disabled: true`，再在「任务计划程序」里停用盯 6700 的任务。控制台脚本已默认不启动守护（要旧行为用 `QQ_GUARD=1`） |
| 面板显示「已就绪」但 QQ 没连上 | 顶部胶囊只说总开关状态，具体原因看它下面那行红字（或「连接」页的「连接体检」）。常见是网关方向反了 / QQ 没开 |
| 一次回两条 | 上游插件没卸干净，或 NapCat 还反向连 6700；向导和大屏自检都会提示 |
| 连不上网关 | 网关是不是**你自己启动**的；地址是不是 `ws://` / `wss://`；token 对不对；Docker 里别填 `127.0.0.1` |
| 面板打不开 service | 先跑 `python -m services --check-deps`（macOS / Linux 用 `python3`），再看 9876 有没有被占用、token 有没有填；也可以直接在面板「概览 → 音频服务」点「测试连接」，那里有带本机目录的启动命令 |
| 改了代码不生效 | 重新跑安装命令并重启 DSH（开发期常见坑） |
| 翻唱报「缺模型 / 路径失效」 | 模型页重新选目录加载，路径已持久化但文件可能被挪走；「语音」页的「本机模型」卡能看到每个引擎现在认的是哪个目录，点「打开文件夹」直接翻出来看 |
| 日志里刷「模型报错：DeepSeek Messages transport failed」 | **不是配置坏了，是这一请求被网络掐断了**。常见于挂代理 / 机场：出口 IP 每隔一两分钟换一次，正在跑的请求就断了（日志里 `egress changed to …` 就是这件事）。插件现在会自动重试 2 次（等 0.6s、1.8s），多数情况自己就过去了；仍然频繁出现就去把代理设成**固定出口**，或给 `api.deepseek.com` 加直连 |
| 生图报 401 / 404 / 「没有返回图片」 | 401 = API Key 不对或没带；404 = 接口地址少写 / 多写了一段（一般填到 `/v1` 为止）；「没有返回图片」= 服务回的 JSON 里没有 `b64_json` 也没有 `url`，多半是模型名写错或额度用完 |
| 自检第 3 步红 | 插件还没上报网关状态：确认「连接」页已连上、service 客户端开关已打开 |
| 换电脑 | 面板「系统 → 备份」导出 zip，新电脑装好 DSH 与**本插件**后拖进同一页恢复；数据目录以外的路径（ffmpeg、模型目录）要重新填 |

数据分两处：

| 位置 | 放什么 |
|---|---|
| `~/.dsh/plugins-data/aurabot/` | 插件自己的配置、人格、表情、日记、记忆、日志、你的模块（内部目录名沿用上游，只为兼容老配置，**不代表品牌归属**） |
| `~/.dsh/plugins-data/qqsoul/service/` | 音频服务的配置、模型路径、翻唱缓存和作业日志（`config.json` 里有接口密钥，别发给别人） |

换电脑时，面板「系统 → 备份」只打包前一处；音频服务的模型和翻唱缓存建议按需重新下载 / 重唱，`config.json` 里的渠道密钥重新填一次更安全。
作业日志在服务数据目录的 `jobs/*.jsonl`；音频成品在 `audio/`；Token 与时间线在 `ops/`。

## 八、账号安全

- 机器人一定用小号。用 NapCat / SnowLuma 这类非官方工具有被限制或封号的风险，主号别拿来当机器人。
- 面板默认只有本机能打开；要远端管理必须显式打开，并务必在反向代理层再加一道认证。
- 备份包里有账号凭证，别发给别人。
